## 2. The idea text (20-2000 characters; `test/submission.test.js` checks the length)

<!-- idea:start -->
```
AI agents buy crypto market data per call and pay in USDC on NEAR, holding no NEAR at all.

Problem: an agent that wants one cent of data today needs an account or key at the seller, a funded wallet, and gas in the chain's native token.

Product: agentfeed-near is a gateway in front of AgentFeed, a live paid crypto-data API for agents (prices, liquidations, funding, summaries). A call answers HTTP 402 in x402 v2 "exact" on near:testnet. The agent signs ONE NEP-366 delegate action carrying one ft_transfer of Circle USDC (NEP-141) and retries; our relayer submits it and pays the gas, and the data comes back in the same request with the settlement transaction. A stock x402 NEAR client and a second library (@fastnear/x402) both pay it unmodified.

Built to fail safely: data is fetched before settlement, the signed relayer transaction is stored before it is broadcast, and a live drill (kill -9 at four points, RPC timeouts) shows the agent is charged once or not at all. A script re-reads every ledger row from the chain. A control shows an account with USDC and almost no NEAR cannot pay the old way but pays ours.

How NEAR fits: NEP-141 USDC, NEP-366 meta transactions, NEP-145 storage registration, sponsored gas. Track: agents pay for data.

Honest status: AgentFeed is an existing product (Solana, Base); only this NEAR integration was built in the window. It runs on NEAR testnet and every payment so far came from the builder's own accounts. The builder's second entry is StakeStreak on NEAR. Live: https://near.ochinimus.app
```
<!-- idea:end -->
